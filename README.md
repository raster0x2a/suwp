# SUWP: Share URL With Password

DBなしで動く、パスワード付きURLシェア用の静的Webアプリです。

- 転送先URLをブラウザ内でJSON化 → gzip圧縮 → AES-GCM暗号化
- 暗号化capsuleを共有URLの `#hash` に格納
- 解除コードは自動生成され、既定コードとしてIndexedDBに保存されます
- 明示的に「解除コードを再生成」しない限り、同じ既定コードで複数のURLをシェアできます
- 共有URLを開くときは、IndexedDBに保存済みの解除コードをすべて試します
- 復号成功後は、その共有URL専用の復号鍵もIndexedDBに保存します
- GitHub Pagesにそのまま公開可能

## ローカル実行

```bash
npm test
npm run serve
```

`npm run serve` 後、表示されたURLを開いてください。

## GitHub Pagesへの公開

1. このディレクトリの中身をGitHubリポジトリへpushします。
2. GitHubのリポジトリ画面で **Settings → Pages** を開きます。
3. **Build and deployment → Source** を **GitHub Actions** にします。
4. `main` ブランチへpushすると、`.github/workflows/pages.yml` がテスト後に `dist/` をデプロイします。

## 使い方

1. 作成画面を開くと、既定の解除コードが自動生成されます。
2. 既定の解除コードはIndexedDBに保存されるため、リロードしても変わりません。
3. 仲間内で同じコードを使い続ける場合は、そのまま転送先URLを入力して「共有URLを生成」を押します。
4. 別の固定コードに変えたい場合だけ「解除コードを再生成」を押します。
5. 表示された共有URLと解除コードを別経路で相手に送ります。
6. 相手は初回だけ解除コードを入力します。
7. 成功後、その端末のIndexedDBに解除コードが保存されます。
8. 以後、共有URLを開くと保存済み解除コードをすべて試し、合うものがあれば自動で開きます。

## 解除コードの扱い

このアプリでは、1つの仲間内グループで同じ解除コードを使い回す前提にしています。

- 作成時は、IndexedDBに保存された既定の解除コードを使います。
- 解除コードを再生成すると、新しいコードが既定コードになります。
- 閲覧時に手入力で成功した解除コードもIndexedDBに保存されます。
- 手入力画面の「この解除コードを今後の作成でも使う」がオンの場合、そのコードが既定コードになります。
- 開く際は、保存済み解除コードを順番に試します。

## セキュリティ上の注意

- この設計では、利便性のために解除コード自体をIndexedDBに保存します。端末やブラウザプロファイルを共有している場合は、その端末上のユーザーが保存済みコードを使える可能性があります。
- 復号成功後は、共有URL専用の `CryptoKey` もIndexedDBに保存します。
- DBを使わないため、配布済みURLの強制失効はできません。
- 共有URLと解除コードが両方漏れると、転送先URLを復号できます。
- 解除コードはURLに含めないでください。
- 共有URLと解除コードは別経路で送ってください。
- GitHub Pagesは公開サイトとして配信されます。リポジトリに秘密情報を含めないでください。

## URL形式

```text
https://your-domain.example/#v1.<encrypted-capsule>
```

`#` 以降に暗号化済みデータを含めます。ブラウザ側で復号するため、サーバーやDBは不要です。
